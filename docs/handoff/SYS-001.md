# SYS-001 — OCR tool

## Summary

`extract_document` posts one local file to `POST /v1/extract` through the shared adapter client. The service returns the JAR-011 envelope. Each item in `data.fields` has a name, a string value, a confidence from 0 to 1, a page, and a four-number bbox. The tool text gives the agent the value and the confidence. A field strictly below `OCR_REVIEW_CONFIDENCE` (default 0.8) is marked `review: low confidence`. 0.8 itself is not.

The POST is not retried. With `OCR_BASE_URL` unset the adapter is a stub: it does not open a socket and it does not invent fields. A timeout, a 5xx, a missing `OCR_API_TOKEN`, or an open circuit is `unavailable` with an empty field list. A body that is missing a bbox (or otherwise fails the field check) is `invalid`, and the rejected value is not shown.

The Research Agent may call the tool. Capability is READ and risk is SAFE.

## Assumptions

- Branch is `jarvis/sys-001`, cut from `jarvis/trd-007` (`f7cd452`), not from `main`. `main` does not contain the adapter client this ticket is required to use. It was not cut from `jarvis/jar-011` alone: that parent is behind the trading stack, and a second D-027 would collide with TRD-001. The pull request targets `jarvis/trd-007` so the diff is only SYS-001. TRD-007 was already committed and pushed. This environment allowed the new branch.
- The service speaks the existing envelope. Fields are `data.fields[]` with `name`, `value` (string), `confidence`, `page` (integer ≥ 1), and `bbox` (four numbers). A bare array with no envelope is invalid.
- "Low confidence" is strictly less than the threshold. The default is 0.8.
- "Stub if unavailable" means an honest unavailable result, not a sample invoice. Inventing a field would poison the reply.
- The tool reads any regular file the process can read, up to 8 MiB, and sends only the base name. The Research Agent is the one granted the tool.
- The commit trailer `Co-authored-by` is inserted by the environment. It was left in place because rewriting history is not allowed. The message itself was written without that line.

## Known gaps

- Nothing points the adapter at a live OCR host. With the base URL unset, extraction says the service is not configured.
- The client is not registered on the health rollup. Health still does not probe upstreams.
- Page coordinates are stored as the four numbers the service sent. This repo does not decide whether they are pixels or fractions.
- A field value that is not a string is rejected. Numbers and dates have to arrive as strings.
- The Research Agent's prompt tells it to quote confidence and not invent fields. There is no second validator that checks the model's narration against the tool text.

## Security impact

- Capability READ, risk SAFE. The name is not order-like, so the order-tool deny does not apply, and the tool does not place, cancel, or transfer anything.
- `OCR_API_TOKEN` is read at call time and placed on `Authorization`. Log lines do not include it. A missing token does not hit the network. `OCR_BASE_URL` and `OCR_REVIEW_CONFIDENCE` are not secrets.
- The local directory is not part of the multipart filename. File bytes are not logged.
- An invalid or unavailable response does not include the rejected field values in the text the agent sees.
- No broker call, no live-trading flag, no mail.
