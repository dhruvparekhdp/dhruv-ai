# TRD-001 — trading-v1 read-only contract

## Summary

trading-v1 is now Pydantic models plus exported JSON Schemas in `docs/contracts/trading-v1/`. Crypto and NSE clients sit on the JAR-011 adapter client and only issue `GET`. Jarvis does not mount `/integration/v1` and has no order, cancel, withdraw, or live-trading path.

Every payload is an envelope: `source_engine` (`crypto-signal-engine` or `nse-trade`), `schema_version` `1.0`, `generated_at`, `data_as_of`, `status` (`ok` / `degraded` / `unavailable`), `is_stale`, `mode` (`paper` / `shadow` / `research`), `correlation_id`, `data`, and `errors`. List routes return `data.items` and `data.next_cursor` and accept `limit` (1–500) and `since`. Prices, quantities, and ratios are decimal strings. Money is `{amount, currency}`.

`decide()` answers 200 only for the eight GET paths, 405 for every other method, and 404 for an unknown GET. `bearer_matches` compares the bearer token with `hmac.compare_digest` and fails closed when the expected token is empty. The clients read `CRYPTO_INTEGRATION_API_TOKEN` and `NSE_INTEGRATION_API_TOKEN`. The contract name on the engine side stays `INTEGRATION_API_TOKEN`.

The trading client keeps the JAR-011 age check and also honors `is_stale`. It returns the full envelope. A body that fails the models becomes `invalid` with the stable detail `response did not match trading-v1`. Timeout, HTTP 5xx, a missing credential, and an open circuit become `unavailable` and do not raise.

## Assumptions

- Branch is `jarvis/trd-001`, cut from `jarvis/jar-011` (`8500c9a`), not from `main`. `main` (`8ba215e`) does not contain the adapter framework this ticket builds on. The pull request targets `jarvis/jar-011` so the diff is only TRD-001. JAR-011 was already committed and pushed; this tree started clean at that commit.
- The engines themselves are not in this repo. This change is the contract and the clients.
- `side` is `buy` or `sell`. Signal status is `active`, `closed`, or `invalidated`. Strategy status is `active`, `paused`, or `retired`. Book is exactly `MIS`, `CNC`, `spot`, or `futures`.
- `period` is a window (`label`, `start`, `end`), not a free string. `params_summary` is one string of at most 500 characters. `change_pct` is a signed decimal fraction (`0.012` means 1.2 percent). Quantity is absolute; `side` carries direction. An open trade has `closed_at` and `pnl` independently null.
- Health and market overview are typed objects. Free text is `details: dict[str, str]`, so a float cannot hide there.
- Currency codes match `^[A-Z]{3,10}$` so `INR` and `USDT` both fit.
- Stale thresholds: crypto 120 seconds, NSE 180 seconds, overridable per client. Age or `is_stale: true` marks the read stale. The envelope is not rewritten.
- Client env names are `CRYPTO_INTEGRATION_API_TOKEN` and `NSE_INTEGRATION_API_TOKEN`. The server-side contract name remains `INTEGRATION_API_TOKEN`.
- JSON Schema is generated by Pydantic (`json.dumps` with sorted keys). `jsonschema` is not a dependency. Tests walk the subset Pydantic emits and also parse with the models. The models are stricter: timestamps must be timezone-aware, and `next_cursor` must be null or non-empty.
- The commit trailer `Co-authored-by` is inserted by the environment. It was left in place because rewriting history is not allowed. The message itself was written without that line.

## Known gaps

- Nothing calls these clients from a mission, a tool, or the adapter registry. Importing them does not register them, so `GET /api/v1/adapters/health` stays empty until a caller registers one.
- There is no process listening on `/integration/v1`. `decide()` and `bearer_matches` are the contract for a server that lives in the engine repos.
- A response with `status: unavailable` is returned as `unavailable` and still carries the parsed envelope when the body matched the schema, so `errors` can be read. Timeout and 5xx carry no envelope.
- `degraded` stays `ok` or `stale`. The envelope's own `status` is how the caller sees the degradation.
- The schema walker does not implement the whole JSON Schema spec. It covers the constructs these files use.

## Security impact

- No mutation route exists. The clients have no method that sends POST, PUT, PATCH, or DELETE. `mode` has no `live` value.
- The bearer compare is `hmac.compare_digest`. An empty expected token does not match.
- The token is placed on the outbound `Authorization` header only. Tests assert it is absent from adapter logs. Validation failures do not return or log the Pydantic error text, which can contain input values.
- A correlation mismatch detail is the fixed string `correlation_id was not echoed`.
- These routes are not mounted on Jarvis, so an unset `JARVIS_PASSCODE` does not expose them.
- No broker or exchange call, no withdrawal, no transfer, no secret written into the repo. The test token is the fake string `test-integration-token`.

## Rollback

Revert the TRD-001 commits on `jarvis/trd-001`, or delete the branch before merge.

Runtime rollback is deleting `app/contracts/trading_v1/` and `app/adapters/trading/`. No schema migration, no new package, no env var read at boot. The Jarvis process does not import these modules.
