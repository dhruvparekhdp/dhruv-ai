# JAR-014 — Tasks

## Summary

Personal tasks live in `work_tasks`, not in the mission `tasks` table and not in the focus-todo list. A task has a title, notes, a due time, a priority from 1 to 3, a status, tags, a recurrence, and an optional link to a mission, a brand, or a content item.

A due value with no timezone is Asia/Kolkata. `2026-11-06T18:30:00` is 18:30 IST, which is 13:00 UTC. A date with no clock is 00:00 IST. The response includes `due_at` in UTC and `due_at_ist`.

Completing a daily, weekly, or monthly task files the next open occurrence in the same series. Monthly recurrence clamps the day: 31 January 2026 is followed by 28 February, and that occurrence is followed by 28 March. A task with no due date uses the completion instant as the anchor. Completing the same series does not file a second row for a due time that is already open.

Agents can only create `suggested`. The store rejects any other status from an agent, and `tasks.suggest` has no status argument. The user accepts a suggestion before it is open. Completing a suggestion is refused. A completed row is frozen.

The user API is passcode-gated: list, create, read, patch, delete, accept, complete. The PWA lists suggested and open tasks, adds one, accepts a suggestion, and completes an open task.

## Assumptions

- Branch is `jarvis/jar-014`, cut from `main` (`8ba215e`). This ticket does not need the adapter, trading, or OCR work, and this environment allowed the new branch. SYS-001 was already committed and pushed on `jarvis/sys-001`. The pull request targets `main`.
- The table is `work_tasks`. The name `tasks` is the mission graph, and the Postgres test reset already drops that table.
- Priority matches the todo scale: 1 is highest, 3 is lowest.
- Brand and content-item links are stored ids. Those tables do not exist, so the id is not looked up and no title is invented. A mission id that is not in the mission store is rejected.
- "Agents may create tasks only as suggestions" is enforced in the store. The user API creates `open` and cannot file `suggested`. Accept and complete are user routes, not tools.
- The next monthly day is clamped from the previous due. 31 January does not return to the 31st in March after February.
- The commit trailer `Co-authored-by` is inserted by the environment. It was left in place because rewriting history is not allowed. The message itself was written without that line.

## Known gaps

- There is no background sweep. Recurrence runs when the user completes the current occurrence.
- The PWA adds, accepts, and completes. It does not edit notes, tags, priority, recurrence, or links; those are on the API.
- The datetime control shows the browser's date format. The value is sent without a zone and stored as IST, which the hint states.
- A brand or content item id is not checked against a catalogue.
- D-026 on this branch is the next decision after `main`. The unmerged stack also appends decisions from D-026 upward. Whichever pull request merges second will need the decision log renumbered.

## Security impact

- Every `/api/v1/tasks` route uses the same passcode gate as the rest of the API.
- `tasks.suggest` is capability WRITE and risk SAFE. It cannot set a status. Accept and complete are not tools, so an agent cannot put a task on the open list or mark one done.
- The tool is not order-like. It does not place, cancel, or transfer anything, and it does not send mail.
- No new secret. Due times and titles are ordinary task data.
