# AGY-003 — Client onboarding and brand profile

## Summary

Each brand can have one onboarding profile and a per-platform access
checklist. Profile fields are goals, audience, positioning, voice description,
words to use, words to avoid, sample posts, competitors, active channels,
approval contacts, and services bought. Queries go through `BrandScope`, so a
profile or checklist row is only visible inside its brand.

The checklist stores a platform, a status (`requested`, `granted`, or
`not_needed`), and notes. The table has no password, token, or API-key column.
Text that looks like a password or a token is rejected, and the error does not
repeat the value. Agency validation errors also omit the submitted value, so a
rejected `password` field is not copied into the 422 body.

`GET /api/agency/onboarding?brand_id=` returns the steps, an integer
completion percentage, and the missing items. A requested access row is still
missing. `granted` and `not_needed` both count as answered. An empty checklist
is one missing item. The percentage stays below 100 until every profile field
is filled and every checklist row is answered.

`services_bought` is a name the owner typed. It does not create an order.
Nothing in this ticket publishes, sends, or calls a channel.

## Assumptions

- The branch is `jarvis/agy-003`, lowercase, created from `jarvis/agy-006`
  (`08939b1`). `origin/main` (`8ba215e`) has no agency package, so a branch
  from main would not compile. This ticket uses `BrandScope` from AGY-006.
  The pull request targets `jarvis/agy-006` so the diff is only this ticket.
  This environment did allow a new branch.
- Profile lists are JSON text on the one profile row. Competitors, channels,
  contacts, and services on the sheet are the onboarding answers. They are not
  foreign keys to `agy_competitors`, `agy_channels`, `agy_contacts`, or
  `agy_service_templates`.
- One profile per brand. A second create is a conflict.
- One checklist row per platform per brand. `other` is a single extra row.
  Platforms are the fixed set in `AccessPlatform`.
- `not_needed` completes that platform. The owner answered. `requested` does
  not.
- Completion is `done * 100 // (done + missing)`, so it reaches 100 only when
  nothing is missing.
- A brand with no profile still has a wizard response. The sheet is treated as
  empty. The route does not invent a stored row.
- The bare word "password" in voice copy is allowed. `password=...`, bearer
  tokens, `sk-` / `ghp_` / `xoxb-` shapes, `AKIA` key ids, JWTs, and private-key
  headers are not. Tests use obvious placeholders, not real credentials.
- Secret rejection lives in the store, so a direct call is refused as well as
  an HTTP call. Unknown keys such as `password` are also refused.
- No new runtime dependency. No LLM call.

## Known gaps

- The checklist does not check that access was really granted. `granted` is a
  label the owner sets.
- Profile competitors and channels are not linked to the operational
  competitor and channel tables. A later ticket can connect them.
- There is one `other` platform row. Extra tools go in the note.
- Search does not cover the profile.
- Offset pagination on the checklist. Fourteen platforms fit in one page.
- The wizard does not email anyone when access is requested.

## Security impact

- New read/write surface for profiles and access notes, behind
  `X-Jarvis-Passcode` when a passcode is configured.
- `agy_access_items` columns are id, brand_id, platform, status, notes,
  created_at, and updated_at. A password cannot be stored as its own column.
- Secret-shaped notes and profile text are rejected before insert, and the
  error text does not include them. Agency 422 responses no longer include the
  submitted value.
- A profile or checklist item for brand A is not returned by a brand B read
  or update.
- No broker, exchange, publishing, email, or ad-network calls. No secrets in
  code, tests, logs, or this document.

## Rollback

Drop the profile and checklist, leaving earlier agency migrations in place:

```bash
python -m agency.migrate down --steps 1
```

That removes `0003`. `agy_brand_profiles` and `agy_access_items` go away.

```bash
python -m agency.migrate down
```

drops every `agy_` table when nothing remains applied.

To remove the feature from the app, revert the AGY-003 commits. Boot still
calls `migrate_up()`. While this code is imported, the next start applies
`0003` again if it is missing.
