# AGY-006 — Personal/client brand isolation

## Summary

Every brand-scoped agency read and write goes through `BrandScope` in
`agency/scope.py`. The helper attaches `brand_id = ?` itself. A missing or
malformed brand id raises before SQL runs. Client, contact and content HTTP
routes require `brand_id` as a query parameter. Omitting it is a 422.

`GET /api/agency/brands` stays unscoped. Brand is the root of the scope, so a
brand list cannot be filtered by a brand id it does not have.

Content cannot change brand. A patch that includes `brand_id`, `channel_id` or
`source_item_id` is refused, and an update addressed at the wrong brand matches
no row. `POST /api/agency/content/items/{id}/duplicate` inserts a new draft in
the target brand, sets `source_item_id` to the source, leaves the source where
it is, and copies no approval rows. The copy starts as `draft` with no channel
and no schedule.

`POST /api/agency/content/items/{id}/schedule` writes `channel_id`, `status` and
`scheduled_at` on this host after `agy_channels.brand_id` matches the item and
the request. The response field `published` is `false`. The handler does not
call a channel, an ad network, or a mailer.

## Assumptions

- The branch is `jarvis/agy-006`, lowercase, created from `jarvis/agy-001`
  (`f22b478`). `origin/main` (`8ba215e`) does not contain the agency package, so
  a branch from main would not compile. The pull request targets
  `jarvis/agy-001` for the same reason. This environment did allow a new branch.
- "One shared helper" is `BrandScope`. `lookup` and `constraint_rows` read a
  single foreign row so a contact can still be checked against a client that
  lives on the owning brand or the client brand. They are not list or search.
- Client and contact owner changes from AGY-001 still work. The row must already
  sit in the brand named by the request, and `allow_brand_change` is limited to
  `agy_clients` and `agy_contacts`. Content has no such path.
- An item that exists under another brand is a 404 from the wrong scope. The
  response does not include that other brand's row.
- "Resets approvals" means the copy has no `agy_approvals` rows and status
  `draft`. The source decision stays on the source.
- Search is a case-insensitive substring on title and body inside the given
  brand. `%` and `_` in the query are literals.
- Scheduling is a local row write. Direct update cannot set status `scheduled`;
  that status only comes from `schedule_item`, which is where the channel brand
  is checked.
- `record_approval` is a store helper so a test can prove the copy does not
  inherit a decision. It is not an HTTP route and it does not publish.
- No new runtime dependency. No LLM call.

## Known gaps

- Leads, projects, tasks, deliverables, campaigns, calendar slots and the other
  brand-scoped tables still have no query functions. A later ticket has to use
  `BrandScope`. There is no second list helper to drift from.
- `GET /brands` is the unscoped exception. Brand create, patch and delete stay
  unscoped because the row is the scope.
- A source item cannot be deleted while a duplicate points at it
  (`ON DELETE RESTRICT` on `source_item_id`).
- Search is not the memory hybrid index. It only scans `agy_content_items`.
- Offset pagination only.

## Security impact

- Client, contact and content lists no longer accept an empty brand. A request
  without `brand_id` is rejected before a query.
- A brand A token of work is not returned by a brand B list, get, search or
  update. Cross-brand content update is rejected.
- Duplicate writes a new id in the target brand. It does not move the source
  and it does not copy an approval.
- Schedule refuses a channel from another brand and does not call that channel.
- The routes stay behind `X-Jarvis-Passcode` when a passcode is configured.
- No broker, exchange, publishing, email or ad-network calls. No secrets in
  code, tests, logs or this document.

## Rollback

Drop only the copy-link column, leaving the AGY-001 schema in place:

```bash
python -m agency.migrate down --steps 1
```

That removes `0002`. `source_item_id` and its index go away. Brand, client and
contact tables stay.

```bash
python -m agency.migrate down
```

drops every `agy_` table, including the bookkeeping table, when nothing remains
applied.

To remove the feature from the app, revert the AGY-006 commits. Boot still
calls `migrate_up()`. While this code is imported, the next start applies
`0002` again if it is missing.
