# AGY-001 — Agency domain model

## Summary

The agency domain lives in the top-level `agency/` package. It has its own
tables (`agy_*`), its own reversible migration (`0001_agency_domain`), and a
router mounted at `/api/agency`. Brand is the root. Every other record,
including every content, project and campaign row, has `brand_id TEXT NOT NULL`.

Pydantic schemas exist for every entity. HTTP CRUD is implemented for Brand,
Client and Contact. On an empty database the seed inserts three brands:
personal (`brd_personal`), agency (`brd_agency`) and a demo client workspace
(`brd_demo_client`).

The repo has no ORM and no migration framework. Agency code uses the existing
dual-dialect layer in `app/core/db.py` and Pydantic, which is how the rest of
Jarvis validates input. This ticket does not call an LLM.

- `agency/models.py` — enums and dataclasses for every entity
- `agency/schemas.py` — Pydantic create/read models; update models for the three CRUD resources

- `agency/migrations/0001_agency_domain.down.sql`
- `agency/migrate.py` — up/down runner and `python -m agency.migrate`

- `agency/router.py` — `/api/agency` routes, passcode-gated
- `agency/docs/erd.md` — Mermaid ER diagram
- `app/main.py` — mount the router and migrate/seed on boot
- `tests/conftest.py` — drop `agy_*` tables between Postgres tests
- `tests/test_agency.py` — migrations, seed, schema invariant, CRUD, HTTP

## Assumptions

- "Use the existing ORM" means `app/core/db.py`. There is no SQLAlchemy or Alembic.
- Package path is `agency/` at the repo root, as the ticket says, not `app/agency/`.
  Mounting the router is the one edit in `app/main.py`, because that is where
  routes are registered.
- `/api/agency` is outside `/api/v1`, so the passcode dependency is declared on
  the agency router. An unguarded client list on a reachable host would be a
  hole. Auth-disabled local dev still behaves like the rest of the API.
- The seed is three **brands**. "Demo client brand" is `Brand.kind = client`,
  not an `agy_clients` row. A Client is the commercial relationship and is
  created through CRUD. It may point at the demo client brand via
  `client_brand_id`.
- A client is owned by a personal or agency brand. A client brand does not own
  other clients.
- A contact's brand is the client's owning brand or the linked client brand.
- Timestamps are ISO-8601 text written in Python (D-005), not `CURRENT_TIMESTAMP`.
- Money is integer minor units. Estimate currency defaults to `INR`. An estimate
  is a quote. Nothing here places an order, sends mail, or changes an ad account.
- `Approval.subject_id` is not a foreign key, so one table can record a decision
  on content, a campaign, a deliverable or an estimate without cascading the
  decision away.
- Deleting a referenced brand, client or contact is refused (`ON DELETE RESTRICT`).
- SQLite foreign keys are enabled on agency connections only. The shared
  `get_conn()` is unchanged.
- Status values such as campaign `active` or estimate `sent` are labels. No
  route publishes, sends, or spends.
- No new runtime dependency.

## Known gaps

- No HTTP CRUD yet for leads, projects, tasks, deliverables, content, channels,
  templates, calendar slots, approvals, campaigns, KPIs, metrics, research,
  competitors, service templates or estimates. Tables and Pydantic models exist.
- A project or content row is not yet checked against its client's brand,
  because those rows are not written by the store. The database still requires
  `brand_id` and a real brand.
- `seed_if_empty` inserts the three brands in three transactions. A crash after
  the first insert leaves a non-empty table, so the next boot will not finish
  the rest. Boot is a single process and the seed is three small inserts.
- Email is validated and lowercased. It is not unique.
- Offset pagination only. No cursor.
- `subject_id` on an approval is not checked against the named table.

## Security impact

- New read/write surface for brands, clients and contacts. It requires
  `X-Jarvis-Passcode` whenever a passcode is configured, same as `/api/v1`.
- No broker, exchange, publishing, email or ad-network calls.
- No secrets in code, tests, logs or this document.
- Foreign keys and `NOT NULL brand_id` stop a row from being stored with no
  brand or with a brand that does not exist.
- Deletes do not cascade. Removing a brand that still has clients returns 409.

## Rollback

From a database that has only migration `0001` applied:

```bash
python -m agency.migrate down
```

That drops every `agy_` table, including the bookkeeping table, when nothing
remains applied. Applying `0001` again afterwards is what the tests do.

To remove the feature from the app, revert the AGY-001 commits. The orchestrator
tables are untouched. Until the code is gone, boot will call `migrate_up()` and
recreate the schema on the next start if the tables are missing and the package
is still imported.
