# JAR-011 — Typed adapter framework

## Summary

External HTTP feeds now share one client in `app/adapters/`. A call returns an `AdapterResponse` (`ok`, `stale`, `unavailable`, or `invalid`). Timeouts, HTTP 5xx, and an open circuit do not raise.

The client sends `X-Correlation-ID`, reads the auth header value from an env var (or an injected secret source) at call time, and applies separate connect and read timeouts. GET requests retry a bounded number of times with full jitter. Other methods are tried once. Each adapter has its own circuit breaker. The body must match the envelope (`data` object or array, ISO-8601 `data_as_of`, optional boolean `stale`). If `data_as_of` is older than that adapter's threshold, the result is `stale` even when the payload says `"stale": false`.

`GET /api/v1/adapters/health` (passcode-gated) aggregates circuit state and the last result. It does not call upstreams.

No new dependency. httpx was already in `requirements.txt`.

## Assumptions

- Branch is `jarvis/jar-011`, created from `main`. AUD-1 stays on `jarvis/aud-1` (already pushed). Lowercase branch name so it survives case-insensitive checkouts. The ticket text said `jarvis/JAR-011`.
- There is no secret-manager client in this repo. `EnvSecretSource` reads `os.environ` at call time. A manager can be injected as anything with `get(name) -> str`.
- The envelope is `data` + `data_as_of` + optional `stale`. Integrations can add a schema callable for fields inside `data`.
- `invalid` is its own outcome so a bad payload is not confused with a dead host. It does not open the circuit, because the host did answer. 4xx/3xx are `unavailable` and also do not open the circuit.
- One logical call records one circuit failure, after retries are exhausted. Three GET attempts on a 500 are not three failures.
- Stale if the timestamp is older than the threshold **or** the engine set `stale: true`. Age overrides an engine that claims fresh.
- Health is last-known state. Probing every feed from this route would trip breakers.
- Naive `data_as_of` values are UTC. Rejecting them would mark feeds that omit the zone as invalid.
- The commit trailer `Co-authored-by` is inserted by the environment. It was left in place because rewriting history is not allowed. The message itself was written without that line.

## Known gaps

- No concrete feed (quotes, filings, anything else) is registered. The registry starts empty; `overall` is `unknown` until something calls `register`.
- Connect-timeout against an unroutable address was not tested. The timeout case is a read timeout on the mock server. Connect errors are mapped to `network` and retried on GET.
- The breaker is in-memory. A restart closes every circuit and forgets the last result, same as the node gateway's live sockets.
- Half-open recovery is unit-tested with a fake clock, not through the mock server.
- The health detail for a missing credential names the env var (`QUOTE_FEED_TOKEN is not set`). It never includes the value. Callers who display `detail` will show the variable name.

## Security impact

- The new route uses the same passcode dependency as the rest of `/api/v1`. A wrong passcode is 401.
- The secret is put on the outbound request header only. Log lines record the adapter name, method, path, outcome, reason, status, correlation id, and, when the credential is missing, the env var name.
- httpx exception text is not logged (`str(exc)` can contain request headers).
- Health snapshots omit `data` and any header.
- No broker or exchange call, no order path, no live-trading flag.
- A schema function that raises cannot leak its message to the agent. The detail is `schema check failed`.

## Rollback

Revert the JAR-011 commits on `jarvis/jar-011`, or delete the branch before merge.

Runtime rollback is removing `app/adapters/`, the health route in `app/main.py`, and the registry import. No schema migration, no new package, no env var the process requires at boot. An unset adapter credential only affects a client that names that variable.
