# OPS-002 handoff

## Summary

Local setup and CI now share one set of commands. `make setup` creates a virtualenv and installs `requirements-dev.txt`. `make lint`, `make typecheck`, `make test`, and `make security` are the checks; `make check` runs all four. GitHub Actions runs those targets on every push and pull request.

Ruff and mypy are configured strictly. Findings that already existed are pinned in `scripts/baselines/` so the current tree passes and a new finding fails. `.env.example` lists every variable the repo reads, with a description and a blank value.

## Assumptions

- The branch is `jarvis/ops-002`. The ticket asked for `jarvis/OPS-002`; this environment requires lowercase branch names.
- CI runs on Python 3.12, the version in `.python-version` and the version used to generate the baselines.
- `make format` exists and is not part of CI. Formatting the existing tree would rewrite the repository.
- `DISPLAY` and `WAYLAND_DISPLAY` are desktop session variables the node agent reads. They are not Jarvis settings and are not in `.env.example`.
- Known advisories are ignored by id so CI can be green without upgrading pinned dependencies. A new advisory id fails `make security`.
- The PWA is vanilla JavaScript under `app/static/`. There is no npm package to audit.

## Known gaps

Lint debt pinned in `scripts/baselines/ruff.txt` (151 findings). The largest groups are unused `noqa` directives, unsorted imports, `datetime.UTC` / `StrEnum` upgrades, unused imports, and `S608` SQL built with the shared `q()` placeholder helper. `E501` is enforced at 120 columns except in `drills/`, where the long lines are embedded lesson text. `S101` is ignored in tests and drills because those files assert on purpose. Pytest fixture arguments are ignored in tests.

Type debt pinned in `scripts/baselines/mypy.txt` (297 findings) under `mypy --strict`. The largest groups are missing annotations on existing tests, `union-attr` / `arg-type` / `index` errors where a value may be `None`, and untyped decorators on the MCP server. Files added for this ticket are not in the baseline. `ignore_missing_imports` is on because groq, fastembed, and PyYAML have no stubs vendored here. `make format` is not gated.

Security debt in `security/pip-audit-ignore.txt`: pillow 11.3.0 (56, transitive via google-genai and fastembed), starlette 0.41.3 (7, transitive via fastapi), mcp 1.2.0 (5), pytest 8.3.4 (1). These were not upgraded. ruff, mypy, and pip-audit themselves had no advisories.

Postgres was not re-run in this session. The new tests do not touch the database. The previous suite was already claimed green on Postgres 16.

## Security impact

- `.env.example` no longer contains a sample passcode or a sample database password. Assignments are blank.
- gitleaks runs against full git history in CI (`fetch-depth: 0`) and locally via a checksum-pinned binary.
- pip-audit runs against `requirements.txt`, `requirements-dev.txt`, and `requirements-mcp.txt`. The ignore file is a baseline, not a fix. The listed advisories remain until someone upgrades those packages.
- CI permissions are `contents: read`.
- No secrets were added to the tree. The canary test contains no credentials.

## Rollback

Revert the OPS-002 commits on `jarvis/ops-002` (`eef8a70` and the revert-plus-handoff commits) and remove the workflow file. The application code from before this ticket does not depend on the Makefile or the new dev packages. The deployed service installs `requirements.txt` only, so the new dev pins do not change production.
