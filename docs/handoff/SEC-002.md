# SEC-002 — HTTP surface hardening

## Summary

The HTTP surface is now an allowlist. Cross-origin browsers are granted access only when `JARVIS_CORS_ORIGINS` names them; a `*` is dropped and is never paired with credentials. Every response carries a same-origin content security policy (`frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and `X-Frame-Options: DENY`. Request bodies are capped (default 1 MiB) and file-shaped content types are refused, because this API has no upload route. Mission starts and model calls (`POST /api/v1/command`, `POST /api/v1/mood`) share one in-process window each. Outside `JARVIS_DEBUG`, a failed turn and an unhandled exception return a fixed sentence; the exception text and traceback stay in the log.

Branch `jarvis/sec-002` was created from `main` (`8ba215e`). The ticket asked for `jarvis/SEC-002`; this environment only keeps lowercase branch names, so the lowercase form is the branch. A new branch was allowed. SEC-001 (authentication hardening) is on `jarvis/sec-001` / pull request 11 and is not in this branch. The two will conflict in `app/main.py` where each one rewrites the middleware block.

## Assumptions

- "CORS rejection" means the browser is not granted the response: no `Access-Control-Allow-Origin` for an unlisted origin. Unlisted `Origin` values are not answered with 403, because a same-origin browser POST sends `Origin` and the host varies (localhost, Tailscale). An empty allowlist keeps the PWA working.
- Credentials are enabled only when at least one explicit origin is configured. The star is stripped before it reaches Starlette, which would otherwise reflect any origin and attach credentials.
- CORS is read when `app.main` is imported. Changing `JARVIS_CORS_ORIGINS` needs a process restart. Body size and rate limits are read per request.
- There is no upload route. "Upload type checks where uploads exist" is a refusal (415) of `multipart/*`, image, audio, video, pdf, zip, gzip, and `application/octet-stream`. JSON stays allowed.
- Rate limits are global to the process, not per address. One user rotating addresses would walk around a per-IP bucket. The windows are in memory and assume one worker; a restart clears them.
- The mission limit runs before a row is inserted. The model-call limit runs after the session-exists check, so an unknown session stays 404 and does not consume the window.
- Outside `JARVIS_DEBUG`, clients see `Engine failure.` or `Internal server error.` Debug mode may include the exception text and a traceback. `/health` never echoes `str(exc)` for a telemetry failure. Product errors that already have a deliberate message (a missing node, a todo rule) are unchanged.
- `connect-src 'self'` is treated as covering same-origin `fetch` and the log WebSocket. If a browser blocks that socket, the exception has to name the page's own host, not a bare `ws:`.
- Unhandled 500s are rendered by Starlette's server-error middleware, which sits outside user middleware. Those responses get the security headers stamped on the response object itself.
- This branch keeps main's passcode model (unset passcode means auth is off). It does not re-implement SEC-001.

## Known gaps

- The rate-limit window is not shared across processes. More than one uvicorn worker would multiply the budget.
- A client that dribbles an endless series of empty body chunks is not specially cut off beyond the byte cap; a declared `Content-Length` over the cap is rejected before the body is read.
- Validation errors (422) still return their field messages. They do not include stack traces.
- Merging this with SEC-001 needs a manual join of the middleware stack in `app/main.py`.

## Security impact

An unlisted website can no longer be granted credentialed cross-origin access by a `*` default. The page cannot be framed, scripts and styles must come from this origin, and a response no longer carries a referrer. A large or file-shaped body is refused before it is stored. A flood of mission starts or model calls is answered with 429 and `Retry-After` instead of running the engine. A crash no longer returns a traceback or a connection string to the client unless `JARVIS_DEBUG` is on.

## Rollback

Do not merge the pull request, or revert the commits on `jarvis/sec-002`. No migration, no new package, no data rewrite. Restart the process on the previous revision and the previous CORS line (`JARVIS_CORS_ORIGINS=*`, credentials on) is what comes back — that is the behavior this ticket removes.
