# TRD-005 — Analyst agents

## Summary

Five analysts are YAML definitions the scheduler dispatches by id: `crypto_analyst`, `nse_analyst`, `portfolio_analyst`, `risk_analyst`, and `trading_research`. Registry load refuses to finish if any of them is missing, granted anything other than READ, or given a tool that is not a trading read.

Their tools are `trading.crypto.read` and `trading.nse.read`. Both call the TRD-001 adapters. Capability is READ and risk is SAFE. `check_permission` denies an order-like tool name (`place`, `cancel`, `amend`, `modify`, `withdraw`, `transfer`, `submit`, `order`, `buy`, `sell`) before the allowlist, and it does not offer approval.

After the model answers, the runner checks the summary against the tool headers:

- `SOURCE` and `DATA_AS_OF` must match every read.
- If any read is unavailable or invalid, the first line starts with `UNAVAILABLE:`.
- Otherwise a stale read must be named on the first line with `STALE:`.
- Exactly one `HOLDINGS:` line. Symbols have to come from a positions read. A signal symbol is not a holding. Anything else fails.
- `## Assumptions` and `## Uncertainty` must be present and non-empty.

A failed check is sent back to the model, up to two retries. The rejected draft is not stored. If the retries run out, the task fails, `result` is empty, and the mission summary does not include the draft.

## Assumptions

- Branch is `jarvis/trd-005`, cut from `jarvis/trd-001` (`f2b28ce`), not from `main`. `main` does not contain the trading-v1 adapters these agents call. The pull request targets `jarvis/trd-001` so the diff is only TRD-005. TRD-001 was already committed and pushed.
- "Register with MissionScheduler" means the existing dispatch path: the scheduler looks up `task.agent_id` in the agent registry. Load fails if an analyst id is absent, so a mission cannot be planned against a missing analyst.
- A holding is the `HOLDINGS:` line, plus a prose claim of the form "holding/holds/held SYMBOL". Other mentions of a symbol are not treated as holdings.
- Only a `positions` read contributes symbols. Signals, trades, and risk names do not.
- Unavailable and invalid reads are both "down". They have `data_as_of: unknown`.
- Two summary retries, then fail. The draft is discarded.
- Client base URLs, when used outside tests, are `CRYPTO_ENGINE_BASE_URL` and `NSE_ENGINE_BASE_URL`. Tokens stay `CRYPTO_INTEGRATION_API_TOKEN` and `NSE_INTEGRATION_API_TOKEN` inside the adapter.
- The commit trailer `Co-authored-by` is inserted by the environment. It was left in place because rewriting history is not allowed. The message itself was written without that line.

## Known gaps

- Nothing points the tools at a live engine. With the base URL unset they report unavailable.
- The echo engine never produces this summary format. Planning without a model key still falls back to the assistant, so an unconfigured process does not dispatch these agents on its own.
- A symbol mentioned in prose without the holding verbs is not rejected. The required `HOLDINGS:` line is what the tests lock.
- The analysts are not given memory or web tools. A later ticket that wants both has to extend the allowlist and the evidence rules together, or a summary could cite a page the adapters did not return.

## Security impact

- No order, cancel, amend, withdraw, or transfer tool exists. A tool whose name matches those verbs is denied even if a definition allowlists it and grants FINANCIAL. Denial does not ask for approval.
- Analysts hold READ only. The trading tools are SAFE, so a read is not turned into an approval prompt.
- Rejected drafts are not written to the task result or the mission summary.
- The tools do not log credentials. A missing base URL reports the variable name.
- These agents do not mount routes and do not change the passcode gate.
